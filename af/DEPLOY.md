# Выкладка в продакшен (Аудиторный фонд)

Краткий чеклист. Подробности в комментариях к `config/database.local.example.php`.

## 1. База и конфиг

- Выполнить скрипты из `sql/` на целевой MySQL **в порядке номеров** в имени файла.
- Скопировать `config/database.local.example.php` → `config/database.local.php`, задать `host`, `database`, `user`, `password`.
- **`runtime_migrations` → `false`** после того, как схема приведена к актуальному виду (без `CREATE`/`ALTER` на каждый HTTP-запрос).
- **`registration_open` → `false`**, если открытая регистрация не нужна.
- **`production` → `true`** — скрыть вывод ошибок PHP в HTML (или задать в окружении **`AUDIT_FUND_PRODUCTION=true`**).
- По **HTTPS**: **`session_cookie_secure` → `true`** (или оставить `null` — включится автоматически при HTTPS).

## 2. PHP и веб-сервер

- Версия PHP **≥ 8.0**, расширения: **pdo_mysql**, **mbstring**, **json**.
- В `php.ini` на проде: `display_errors=Off`, `log_errors=On`, корректный `error_log`.
- При необходимости: `composer install --no-dev --optimize-autoloader` в корне проекта.

### Apache

- Включены модули, чтобы срабатывали **`.htaccess`** в `config/`, `includes/`, `storage/`, `sql/`.
- После установки: переименовать **`install/.htaccess.production`** → **`install/.htaccess`**, чтобы закрыть каталог установки (перед повторным мастером — временно убрать).

### Nginx

- Аналог `Require all denied` — `location` с `deny all` для `config/`, `includes/`, `storage/`, при необходимости `install/`.
- Пример переменной окружения: `fastcgi_param AUDIT_FUND_PRODUCTION true;` (если используете FPM).

## 3. Права и секреты

- Каталоги **`storage/login_rate_limit`** и **`storage/register_rate_limit`** — **запись** для пользователя PHP.
- Файл **`config/database.local.php`** не попадать в публичный репозиторий (уже в `.gitignore`).

## 4. Мастер установки

- В **`includes/install_lib.php`** функция **`audit_fund_install_wizard_enabled()`** на проде обычно **`false`** (уже по умолчанию).
- Каталог **`install/`** после ввода в эксплуатацию лучше закрыть `.htaccess` или удалить с сервера.

## 5. Резервное копирование

- Регулярный дамп БД и при необходимости копия `config/database.local.php` вне сервера (безопасное хранение).

## 6. Яндекс и общий вход с Вектором

Кнопка «Продолжить через Яндекс» по умолчанию идёт через Вектор (`yandex_oauth_mode` = `relay`): в кабинете Яндекса уже указан `https://planiro75.ru/public/auth/yandex_callback.php`, второй адрес добавлять не нужно. После согласия сессия открывается и в Векторе, и здесь.

Страница входа сама спрашивает соседний сайт. Если человек уже вошёл в Вектор, аудиторный фонд откроется без пароля. Пользователи аудиторного фонда уже есть в Векторе и входят через Яндекс: обратный переход открывает эту учётку по идентификатору Яндекса или по той же почте и не создаёт новую. Если в аудиторном фонде почта пустая или не совпадает, первый вход — кнопкой «Продолжить через Яндекс»: Вектор находит своего пользователя, а здесь учётка привязывается по почте или по уникальному ФИО. Совсем новый человек из Вектора, которого ещё нет в аудиторном фонде, получает роль «пользователь».

Секрет `sso_secret` в `includes/database.php` и в `config/config.php` Вектора должен совпадать. Выход из одного сайта завершает сессию и во втором.

Прямой callback Яндекса на этом сайте: добавьте в приложение OAuth адрес `https://af.zabedu.ru/yandex_callback.php` и поставьте `'yandex_oauth_mode' => 'direct'`. Для уже работающей базы выполните `sql/migrations/009_users_oauth_yandex.sql`.

Отдельный вход без общей сессии: `index.php?sso=skip`.

## 7. Проверка после выкладки

- Вход под администратором, расписание, заявка, отчёты (роль staff).
- Убедиться, что по прямому URL нельзя скачать файлы из `config/` и `includes/` (ожидается **403**).
