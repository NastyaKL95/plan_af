# Техническое задание: веб-портал конкурсов (региональный контекст — Забайкальский край)

## 1. Общие сведения

| Параметр | Значение |
|----------|----------|
| **Назначение** | Единая точка входа для публикации конкурсов, приёма заявок и согласий, проведения этапов, экспертной оценки, публикации новостей и информации о партнёрах. |
| **Тип** | Веб-приложение (серверный рендеринг HTML), без SPA-сборщика. |
| **Репозиторий / продукт** | Проект «Конкурсы — PHP» (`iro/php-rewrite`). |

## 2. Цели системы

1. Информировать пользователей о конкурсах, сериях конкурсов, новостях и объявлениях.
2. Обеспечить регистрацию, вход в личный кабинет и ведение профиля участника.
3. Поддержать полный цикл участия: заявка → модерация согласия и документов → прохождение этапов → подача работ → оценка экспертами → фиксация наград (при необходимости).
4. Разделить доступ: публичная зона, участник, модератор конкурса, эксперт, администратор сайта.

## 3. Роли и права

- **Гость** — просмотр опубликованного контента в рамках видимости конкурсов.
- **Зарегистрированный пользователь** — профиль, участие в конкурсах (если не ограничено ролями), уведомления.
- **Участник конкурса** — пользователь, зачисленный в `contest_participants` после одобрения согласия (или по правилам конкурса).
- **Модератор конкурса** — назначен на конкурс (`contest_moderators`): согласия, файлы участников, этапы, отчёты, награды и др. в пределах конкурса.
- **Эксперт** — пользователь из пула конкурса / назначенный на этапы: доступ к работам и оценкам по правилам этапа.
- **Администратор сайта** (`is_superuser` / системные роли) — глобальное управление пользователями, конкурсами, контентом сайта, шаблонами согласий, архивом и т.д.

Ограничения бизнес-логики: администратор сайта, модератор конкурса и эксперт этапа **не могут** подавать заявку на участие в том же конкурсе (блокировка подачи заявки).

## 4. Функциональные требования

### 4.1. Публичная часть

- **Главная (`/`)**  
  - Поиск конкурсов по названию/описанию.  
  - Фильтр по календарной фазе: «Скоро начнётся», «Идёт конкурс», «Завершён».  
  - Режим отображения: карточки / список (`view=cards|list`).  
  - Частичное обновление списка конкурсов через AJAX (`/partial/home-contests/`).  
  - Блок «Новости и объявления» (до 3 записей) со ссылкой на полный раздел.  
  - Блок «Партнёры» (логотипы, опционально внешние ссылки), анимация/оформление по текущей вёрстке.

- **Каталог конкурсов (`/contests`)** — список опубликованных неархивных конкурсов со статусом, удовлетворяющим условиям отбора в коде.

- **Карточка конкурса (`/contest?id=…`)**  
  - Описание, даты, изображение, ссылка на регламент/документы при наличии.  
  - **Внешний конкурс** (`is_external`): вместо этапов на портале — переход по внешней ссылке.  
  - **Обычный конкурс**: этапы, текущий этап (в линейном режиме), режим параллельных этапов при соответствующей настройке конкурса.  
  - Для авторизованного: статус участия, согласие, кнопки «подать заявку», «загрузить согласие», подача работы на этапе, список своих работ, средние баллы (где применимо), призовое место при наличии записи в `awards`.  
  - Видимость конкурса для пользователя — по правилам `contest_is_visible_to` (скрытые/черновики недоступны публично).

- **Новости (`/news`, `/news/show?id=…`)** — публикации из `site_announcements`: список с пагинацией, просмотр материала; учёт `published_at`, закреплённые записи.

- **Серии конкурсов (`/series`, `/series/{slug}`)** — список серий, у которых есть опубликованные конкурсы; на странице серии — конкурсы серии.

- **Статические страницы** — минимум: политика cookie (`/cookies`), политика конфиденциальности (`/privacy`).

- **Ошибки** — страницы 404, 403 с навигацией (хлебные крошки).

### 4.2. Аутентификация и профиль

- **Регистрация (`/signup`)** — создание пользователя с валидацией (реализация в `Auth::register`).
- **Вход (`/login`)** — email/пароль (или настраиваемое поле логина при внешней аутентификации); опционально **лимит неудачных попыток** с IP; опционально **внешняя БД** (`external_auth`); опционально **Яндекс OAuth** (`oauth.yandex`, без ограничения домена email); неактивные учётки (`is_active = 0`) не входят.
- **Восстановление пароля** — `/forgot-password`, `/reset-password` (таблица `password_reset_tokens`, письма через `mail` в config).
- **Выход** — завершение сессии.
- **Профиль (`/profile`)** — редактирование ФИО, даты рождения, региона, муниципалитета, школы и т.д.  
- **Просмотр профиля (`/profile/view?profile_id=…`)** — владелец или администратор.

### 4.3. Участник: заявка и конкурсный процесс

- **Подача заявки (`/contest/apply?contest_id=…`)**  
  - Загрузка файла согласия (допустимые расширения: PDF, DOC, DOCX).  
  - Загрузка обязательных вложений по полям конкурса (`contest_attachment_fields`).  
  - После отправки — уведомление модераторам конкурса.  
  - Повторная подача при отклонении согласия; дозагрузка документов при одобренном согласии, но неполном пакете.

- **Модерация согласий** выполняется модератором (см. п. 4.4); после одобрения пользователь становится участником (`contest_participants`), с учётом флага «явное допускание по этапам» у конкурса.

- **Подача работ на этап** — форма с файлом работы, ссылкой, опциональными вложениями по полям этапа; ограничения по датам этапа, дедлайну, допуску к этапу.

- **Дополнения к работам** — сценарии модерации доп. материалов (статусы отклонения/принятия в модели данных).

- **«Мои конкурсы»** — сводка участия пользователя.

- **Уведомления (`/notifications`)** — внутриигровые уведомления (`in_app_notifications`): прочитано/не прочитано, ссылки на релевантные страницы.

### 4.4. Модератор конкурса

- Просмотр и **одобрение/отклонение** заявок (согласий) с причиной отказа; при одобрении — зачисление участника; при отказе — снятие участия.  
- **Согласия и файлы к работам** — список заявок, вложения участников, связанные сущности.  
- **Архив материалов участников** — выгрузка (в т.ч. ZIP по участнику).  
- **Этапы**: создание/редактирование этапов с датами, форматом (онлайн/очный), режимом оценки (все эксперты этапа / назначенные), числом экспертов на работу, критериями и группами критериев, вложениями к этапу, внешними ссылками.  
- **Назначение экспертов**, отчёты по конкурсу, статистика, награды, финальные операции — в объёме, реализованном в `routes_moderator_*`.  
- Уведомления участникам при ключевых событиях (одобрение/отказ и др.).

### 4.5. Эксперт

- Список конкурсов и этапов, где пользователь — эксперт.  
- Доступ к работам в рамках правил этапа (все работы / только назначенные).  
- **Выставление баллов** по критериям, комментарии.  
- Ограничения на массовую рассылку уведомлений экспертам в режиме «все эксперты» (порог в конфиге).

### 4.6. Администратор

- **Панель (`/admin`, `/admin/panel`)** — доступ при глобальных правах на управление.  
- **Пользователи** — список, редактирование, роли, активность.  
- **Конкурсы** — создание/редактирование, модераторы, пул экспертов, поля вложений заявки, внешние ссылки, серия, архивация, выгрузки.  
- **Новости/объявления** — CRUD, публикация, закрепление.  
- **Партнёры сайта** — логотип, ссылка, сортировка, активность.  
- **Шаблоны согласий** — файлы-шаблоны для скачивания/справки.  
- **Серии конкурсов** — тематические серии с обложкой и slug.  
- **Системные роли** — справочник.  
- **Архив конкурсов** — список архивных записей; при архивации — формирование отчёта (Excel), очистка данных конкурса по описанной в проекте логике.  
- Редиректы совместимости со старыми URL (`/manage-users` → `/admin/users` и т.д.).

### 4.7. Общее для интерфейса

- Общий **макет** с шапкой, навигацией, flash-сообщениями, Bootstrap и кастомным `styles.css`.  
- **CSRF-защита** форм, **безопасные заголовки** (CSP и др.) — по конфигурации.  
- **Загрузки файлов** в структурированные каталоги (`public/uploads/...`) с удалением старых файлов при замене.

## 5. Нефункциональные требования

- **Сервер**: PHP **8.2+**, расширение PDO, MySQL **8+**.  
- **Без фреймворка**: один фронт-контроллер (`public/index.php`), маршруты — явные условия по `$uri`, при необходимости алиасы в `route_aliases.php`.  
- **База данных**: скрипт `database/schema.sql`, при необходимости миграции `database/migration_*.sql`.  
- **Сессии**: PHP-сессии, параметры cookie настраиваются (Secure, SameSite, domain).  
- **Логирование**: опционально JSON-логи в `storage/logs`.  
- **Производительность**: классические требования к индексам и пагинации для списков новостей и больших выборок.  
- **Доступность и UX**: частично заложено в шаблонах (`aria-*`, подписи к разделам).

## 6. Данные (основные сущности)

Пользователи, роли, конкурсы, серии, модераторы и пул экспертов, поля вложений заявки, согласия пользователей, участники, этапы, эксперты этапов, критерии и группы критериев, работы (submissions), назначения экспертов на работы, вложения к работам, оценки, награды, новости сайта, партнёры, внутренние уведомления — в соответствии с `database/schema.sql`.

## 7. Развёртывание

- Document root веб-сервера — каталог **`public`**.  
- Конфигурация: копия `app/config.example.php` → `app/config.php`, параметры БД и опций приложения.  
- Локальный запуск: встроенный сервер PHP из `public` или виртуальный хост (в т.ч. OpenServer на Windows), см. `README.md`.

## 8. Вне охвата / примечания

- ТЗ отражает **текущую** реализацию; отдельные опции (внешняя авторизация, CSP, rate limit входа) включаются конфигом и могут быть выключены в среде разработки.  
- Канонические «красивые» URL для новостей в интерфейсе могут использоваться вместе с алиасами роутера — см. `app/http/route_aliases.php`.
